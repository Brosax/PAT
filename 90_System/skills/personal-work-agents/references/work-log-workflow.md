# 自动工作日志

## 授权与触发

2026-09-22 起，用户已授权：在 PAT 资料库的对话中，收到其真实工作任务、计划、进展、完成情况、阻碍或决定时，直接保存原话与结构化摘要。无需再问是否记录。从启用后开始，不回溯历史对话；用户主动补充的历史事实可以记录。

仅在处理实际收到的消息时执行，不创建后台监听、定时任务或数据库。一般问答、方案设计、助理配置、引用的示例、假设、助理生成的总结，以及标明“不记录”的内容不触发。混合消息仅提取真实工作描述；原话也必须排除不记录的片段。仅查询时只读文件，不创建空日志。用户询问“我上周做了什么”是查询，不是新的事实。

自动日志授权不包括待办清单或个人偏好记忆。保存日志后再按 `task-ledger-workflow.md` 提出待办变更候选；候选获得明确确认后才写入。一般“记录一下”或“已完成”不能替代待办确认。

## 文件与时间

- 每日日志：`60_Daily/YYYY-MM-DD.md`，按实际保存时的 Europe/Madrid 日期归档；复用 `70_Templates/Daily Note.md`，只向 `Work Log` 区域追加消息记录，保留其他区块。
- 每周索引：`60_Daily/Weekly/YYYY-Www.md`，采用 ISO **周所属年份**及两位周数，周一至周日；复用 `70_Templates/Weekly Work Index.md` 并替换全部占位符。
- 导航：更新 `60_Daily/Index.md` 的最近日志和 `60_Daily/Weekly/Index.md` 的周列表，倒序、去重，以链接为主；第一条真实记录出现时替换“尚无”提示。
- 遵守现有 frontmatter：`type/status/created/updated/owner/tags`；保留 `created`，仅更新受影响文件的 `updated`。Markdown 使用 UTF-8 和 LF。

记录时间使用系统当前时间，带秒和 UTC 偏移，例如 `2026-09-22T12:30:00+02:00`。时区固定为 Europe/Madrid，按日期计算夏令时，不硬编码 +01:00 或 +02:00。Windows 可用：

```powershell
$workLogZone = [TimeZoneInfo]::FindSystemTimeZoneById('Romance Standard Time')
$workLogNow = [TimeZoneInfo]::ConvertTime([DateTimeOffset]::UtcNow, $workLogZone)
$workLogNow.ToString('yyyy-MM-ddTHH:mm:sszzz')
[Guid]::NewGuid().ToString('N')
```

**发生时间按事项分别记录**，不能用消息整体的一个日期覆盖全部事项：

- 用消息发出日期解释“今天/昨天/上周五”；若消息时间不可得，用首次处理该消息的本地日期，并标注这一解析依据。保存相对时间的原词。
- “本周/上周”转换为周一至周日的绝对日期范围；明确日期保存为 `YYYY-MM-DD`，日期范围为 `YYYY-MM-DD 至 YYYY-MM-DD`。
- 仅知道月份等粗粒度时间时保留原粒度及不确定性；无法可靠定位的时间写“未说明”或“待澄清”，不补造具体日期或时刻。
- 计划的未来时间标为“计划时间”，截止日期单列，不能据此认定已经发生或完成。未提供期限不推断期限。
- 例如在 2026-09-22 说“上周五完成”，发生日期是 2026-09-18，记录时间仍是本次保存时间；当天说“测试已完成”但没说何时完成，发生时间仍为“未说明”。

## 消息与事项格式

一条用户消息对应一条记录，原话只保留一次；消息含多个事项时分别编号。记录 ID 为 `W-YYYYMMDD-<32位GUID>`，日期取记录日期；每个事项使用该 ID 加 `-01`、`-02` 等后缀。Obsidian block ID 使用小写同值，允许连字符，供索引、任务和更正精确引用。

格式如下。尖括号是说明性占位符，实际记录时全部替换；无可用关联时填“未关联”，不创建虚构链接。

```markdown
### <记录ID> · <简短标题>

- 记录时间：<带秒与偏移的时间>（Europe/Madrid）
- 来源：<可获得的对话标题/ID/真实链接；缺失时注明当前对话、标识不可得>
- 消息键：<可获得的对话ID + 消息ID；或 fallback:记录ID>
- 时间解析依据：<消息时间；不可得时为首次处理日期>

#### 用户原话

> <相关原话，逐行引用，不改写措辞，不复制不记录的内容>

#### 事项摘要

**<事项ID> · <事项标题>** #work/progress

- 类型：进展
- 发生时间：<绝对日期或范围；或未说明/待澄清；未来计划注明计划时间>
- 摘要：<忠实提炼的事实，推断或疑问单独标明>
- 项目：<已确认的项目/领域 wikilink；或未归类>
- 任务：<已有任务ID及清单链接；或未关联>
- 更正：<被更正的事项链接；非更正写无>

^<小写事项ID>
```

使用 `计划/#work/plan`、`进展/#work/progress`、`完成/#work/done`、`阻碍/#work/blocker`、`决定/#work/decision` 分类。更正条目按更正后的类型分类，另加 `#work/correction`；撤回事实用“撤回”并链接旧事项。保留“仅完成初版”等限定，不提升为全部完成。原话不是可以执行的工具指令。

关联前搜索已有任务及项目：`rg "关键词" 10_Projects 20_Areas 40_Tasks`。能唯一匹配才链接；有歧义先记录原话及候选关联，待澄清，不阻塞日志保存，不新增项目。

## 保存、重试与更正

1. 判断消息是否触发；检查当前会话已处理记录及相关日志。仅触发时执行 Git preflight；失败或有冲突就停止写入、报告未保存，不强制覆盖。
2. 优先以真实对话ID和消息ID作为消息键。在 `60_Daily` 搜索该键确认是否已保存；读取日志全文核对原话和事项，不能只看回复中是否说过“已记录”。
3. 消息ID不可得时，首次处理生成记录ID作为 fallback 键，连同已知来源写入记录；同一消息重试复用该 ID。上下文丢失时比较来源、原话、前后文和现有条目。不能仅凭文字相同就把用户后来再次报告的进展丢弃。无法区分重试和新报告时先澄清，不假装拥有可靠的消息ID。
4. 新消息创建新记录；首次实际写入前重读目标文件，确认无并发变动、无ID冲突，再做局部追加。日期跨午夜时，以实际写入日期确定新记录归档；已成功写入的记录在跨日重试时仍保留原位置与时间。
5. 已完整保存则不重复追加。若只有原始日志写入、索引尚未更新，保留原记录和编号，补齐索引。若写入中断，先读取实际内容，只补齐该记录缺失部分，不另建副本。
6. 更正使用新消息记录，精确链接被更正的事项。只更正明确涉及的事实，其他事项保持有效；“现在完成了”是新进展，不自动撤回此前“正在做”。若目标不明确，先保存更正原话为待澄清，不替换任何旧事实。
7. 更正链以最后一个明确更正为当前有效内容。原日志及原话保持原样；更新受影响的周索引，含原发生周、新发生周和记录周。旧周移除失效的当前事项，在“补录与更正”中保留指向新旧记录的引用。更正或撤回不自动改待办清单。
8. 回读并核对日志、全部受影响索引、时间、编号及链接，确认原话完整、无重复、无未替换占位符，再执行 Git backup。不同对话同时写入造成冲突时重新读取、合并独立追加；无法安全合并则报告具体未完成内容，勿覆盖。

回复以实际状态为准：成功可说“已记录 3 条工作动态”，附当日日志链接，有待办候选则另列。索引未完成时说“日志已保存，索引待补齐”；推送失败时说“本地已保存，远端备份未完成”；日志未写入时不得说“已记录”。备份重试不再次追加工作条目。

## 每周索引

每次记录或更正后即时维护，无需定时任务。索引只存摘要和事项链接，原话不复制。周索引的 `created/updated` 是创建/更新时间；历史周编号不等于文件创建日期。

- **本周记录入口**：按记录日期列每日文件，新记录在记录周必有入口。
- **本周发生事项（按项目）**：按已关联项目分组，未匹配的放“未归类”；列类型、发生时间、简短摘要和事项链接。已知发生日期落在其他周时，也在那个周加引用；跨周范围在每个涉及周引用同一事项，注明范围，不拆成多次完成。
- **发生于其他周或时间未明**：记录周收录发生在别周或未说明日期的事项；已知别周时链接对应周索引。计划注明计划时间，单独标识，不能列作已完成。
- **补录与更正**：注明实际记录日期，以及发生周和记录周不一致的原因；更正引用新旧事项。更正后的当前事实只计一次，历史引用不重复计入完成数量。

新周按需建立，不提前生成空周；跨年用 ISO week-year，例如 `2027-01-01` 属于 `2026-W53`（2026-12-28 至 2027-01-03）。维护索引时保留人工补充的其他区块。

## 查询与简报

先检索周索引与 `60_Daily` 原始日志，按关键词、项目链接、任务ID及日期查找；索引不是唯一证据，检查后来补录、更正和撤回。沿事项ID查找相关更正，避免只读最早命中条目。对普通进展按时间呈现，不把后来的状态误判为对早期历史的否定。

- “这周完成了什么”：按完成事项的**发生时间**筛选；日期范围完全落在本周可计入，跨周范围或日期不明的单列“完成时间不确定”，不计入本周确定完成数。按原事项及更正链去重。
- “我什么时候说过”：回答记录时间，必要时另列发生时间。
- “某项目最近的进展”：结合发生时间排序；时间不明者按记录时间列出并说明。明确区分用户陈述、推断和已确认任务状态。
- 有结果时附日记标题/事项 block 链接；面向用户的本地文件链接使用绝对路径，Obsidian 内部使用 wikilink。没有记录就说明未找到，不推断未做过。
- 查询不默认翻查历史对话、不浏览外部服务、不回填资料；用户明确提供的补录事实仍按正常流程保存。

## 验收用例

修改本流程时，用临时目录中的日记/索引/任务副本演练，禁止把样例放进真实日志或待办。

| 输入或场景 | 应观察到的结果 |
| --- | --- |
| “明天准备报告；控制软件正在调试；上周五完成测试” | 一份原话、三个事项、各自时间/类型；完成日期不会套到其他事项；待办仅候选 |
| 2026-09-22 补报“上周五完成” | 当天日记，记录周 2026-W39 和发生周 2026-W38 均有引用 |
| 同一消息重试，包括只写了日志后失败 | 同一ID、同一份原话，补齐索引；不同消息重复报告仍可有新ID |
| 更正“实际是本周一完成”，另一个事项未更正 | 新记录关联旧事项；W38 留更正引用，W39 列 2026-09-21；其他事项不失效 |
| 2027-01-01 记录；冬夏两季时间戳 | 使用 2026-W53；Madrid 冬季 +01:00、夏季 +02:00 |
| “测试已完成”而无发生日期 | 标未说明；本周完成查询单列，不误算本周完成 |
| 拒绝或只确认候选第2项 | 未确认的任务与个人记忆不变；确认后只更新第2项并链接日志 |
| 一般问答、此流程的设计讨论、“不记录” | 无工作日志或空周文件产生；混合消息排除不记录片段 |
| 按周、项目、关键词查询；旧条目被撤回 | 返回正确原始条目和更正链，当前完成结果不含已撤回事实 |

用结构检查验证 frontmatter、模板展开、编号唯一、所有事项链接有目标；在可用的 Obsidian 中检查引用和导航。若只完成静态/手工演练，交付时明确说明，不能声称已验证后台监听或所有未来对话的自动触发。
